# MTA Design Director

Use the repository as the deterministic building compiler and use model judgment to direct a short, evidence-backed candidate loop.

## Quality target

Optimize for `candidate_ready`: a coherent architectural proposition with fitted program, legible circulation, coordinated structure/envelope, intact geometry, and presentation views suitable for critique.

Keep `professional_review_required` visible for site, code, fire, accessibility, lateral, connection, fabrication, Rhino acceptance, and other unresolved professional checks. Never promote, sign, or relabel them.

## Required context

1. Read `PROJECT_CHARTER.md`.
2. Read `references/closed-loop-protocol.md`.
3. For source changes, read the ADRs and tests named by the modules being changed.
4. For any redline item, read `docs/decisions/0021-review-evidence-architecture.md` before proposing a fix.

## Closed loop

1. Establish the input contract: source, licence, exact SHA-256, design goal, output directory, compiler fingerprint, and authority boundary.
   When the goal includes diversity across recordings, hold typology constant and run
   the Program Volume diversity preflight in `references/closed-loop-protocol.md`
   before any multi-track native export.
2. Generate a baseline through a public repository entry point. Keep v2 and v3 evidence, reports, drawings, GLB, Blend, and review views bound to one run ID.
   When the task names Program Volumes, run the explicit `program_volume` v3 mode and package the native Blend; a legacy-mode result cannot stand in for that protocol.
3. Inspect machine evidence before visual judgment. Preserve every failure, unknown, provisional exclusion, and unevaluated check.
4. Review every required view. Grade silhouette, entry, spatial hierarchy, program legibility, circulation, structure/envelope agreement, facade rhythm, and presentation clarity. Cite view IDs and observable evidence.
5. Classify findings as compiler defect, candidate-variable issue, presentation issue, or professional-review item.
6. Iterate through the narrowest legal input surface. Prefer controlled candidate choices, score-authorised datums, pins, and structured massing inputs. Do not hand-edit GLB/Blend geometry or weaken a gate.
7. Recompile from source after any architectural change. A presentation-only adjustment may alter camera, light, or material staging while retaining the same model/run identity rules.
8. Compare baseline and revision against the same rubric. Select only when the revision improves the named finding without regressing hard gates.
9. Package the selected candidate with source provenance, run/model/compiler identities, machine results, visual review, before/after views, and unresolved professional review.

Raw topology hashes do not prove form diversity. A normalized Program Volume collision
is a compiler finding: keep it visible, fix the score-to-form control surface, rerun the
preflight, and withhold any stable-diversity claim until the collision is gone.

## Stop conditions

- Stop after two architectural iterations unless the user asks for a longer search.
- Stop immediately if compiler source changes during a run, evidence hashes diverge, or the input licence cannot be verified.
- Do not publish to `artifacts/model_versions/latest`, write Rhino acceptance, or mark site/code values verified.
- If a defect requires compiler code changes, report the root cause and create a separate repair task; keep this candidate run reproducible.

## Output standard

Return the selected candidate first, then the evidence that earned selection. Always state:

- music/brief source and licence;
- selected typology, massing, structure, and facade grammar;
- runtime, element count, and machine-gate summary;
- visual finding changed between rounds;
- remaining professional-review items;
- direct paths to the report, model, drawings, and hero/review images.
- for Program Volume runs, the volume contract/grammar, detail-readiness status, native Blend, and Rhino candidate status.
- for diversity runs, the measurement-only normalized-shape report, collision count,
  fixed typology, music set, and the full-loop candidates that survived preflight.
